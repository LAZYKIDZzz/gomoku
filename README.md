## 项目内容

```
claude-test/
├── README.md                ← 本文件
├── gomoku.html              ← 前端：联网客户端（Canvas + SSE + fetch）
├── server.js                ← 后端：Node.js 零依赖 HTTP + SSE 服务端
└── random_number_picker.py  ← 与本项目无关的独立 CLI 小工具
```

| 文件 | 行数 | 说明 |
|------|------|------|
| `server.js` | ~210 | 单文件后端：HTTP 静态分发 + SSE 实时广播 + REST 落子 / 撤销 / 重开。仅依赖 Node.js 标准库。 |
| `gomoku.html` | ~750 | 单文件前端：HTML + CSS + Canvas 棋盘 + 联机逻辑。无构建步骤、无打包工具。 |
| `random_number_picker.py` | ~90 | 交互式 CLI，从用户输入的 10 个数字中随机抽取。可独立运行，与五子棋无关。 |

**核心特性**

- 🌐 **真正的两人联机** —— 同一 Wi-Fi 下分享链接即可对战
- ⚡ **零依赖** —— `node server.js` 直接跑，不需要 `npm install`
- 🎨 **大胆视觉** —— 新粗野主义，电光柠绿 / 霓虹品红双主色，巨幅展示字
- 🔄 **断线重连** —— 15 秒宽限期内刷新 / 重连可保住槽位
- 👀 **观战模式** —— 第三个连接自动成为观战者，可看完整对局
- 🎯 **服务器权威** —— 所有规则判定在服务端，客户端只渲染快照

## 快速开始

### 环境要求

- **Node.js ≥ 14**（用于运行服务端）
- 任何现代浏览器（Chrome / Firefox / Safari / Edge），支持 `EventSource` 与 ES2017+
- 两台设备需连接 **同一 Wi-Fi**（或可互通的内网）

### 启动服务器

```bash
cd claude-test
node server.js
```

启动后控制台会打印：

```
  GOMOKU // PROTOCOL SERVER
  ────────────────────────────────────────────────
  Local    →  http://localhost:8080
  Network  →  http://192.168.1.42:8080      ← 把这个发给对手
  Network  →  http://192.168.8.233:8080
  ────────────────────────────────────────────────
  把 Network 链接发给对手 (需连同一 Wi-Fi)，打开即可对战。
  Ctrl+C 退出。
```

### 自定义端口

```bash
PORT=9000 node server.js
```

### 开始对战

1. 第一位玩家打开 `Local` URL（或 Network URL），自动成为 **PLAYER 01**
2. 把任一 **Network URL** 发给对手（在同一 Wi-Fi 下）
3. 对手打开后自动成为 **PLAYER 02**
4. 棋盘解锁，**P01（电光柠绿）先手**
5. 顶部 `TURN` 横幅会提示当前轮到谁
6. 5 子连珠即获胜，弹出胜利动画后点 `PLAY AGAIN` 重开

> 第 3 个及以后的连接会自动变为 **SPECTATOR**（观战），可以看牌但不能落子。

## 架构与协议

### 通信模型

```
┌─────────────┐   GET /events (SSE)    ┌──────────────┐
│             │ ◀──────────────────────│              │
│  Browser A  │                        │              │
│  (Player 1) │   POST /move           │              │
│             │ ──────────────────────▶│   Node.js    │
└─────────────┘                        │   server.js  │
                                        │              │
┌─────────────┐                        │  权威状态机  │
│  Browser B  │ ◀── SSE broadcast ────│              │
│  (Player 2) │ ─── POST /move ──────▶│              │
└─────────────┘                        └──────────────┘
```

服务端在每次状态变化（落子 / 撤销 / 重开 / 玩家上下线）后向**所有连接的客户端**广播完整快照。客户端只需渲染，不维护本地权威状态。

### HTTP 端点

| 方法 | 路径 | 用途 | 鉴权 |
|------|------|------|------|
| `GET` | `/` | 返回 `gomoku.html` | 无 |
| `GET` | `/events?id=<sessionId>` | 建立 SSE 长连接，订阅状态广播 | 通过 `id` 识别会话 |
| `POST` | `/move` | 落子 `{id, r, c}` | 必须是当前回合方 |
| `POST` | `/undo` | 撤销最近一手 `{id}` | 非观战者 |
| `POST` | `/restart` | 重置棋盘（保留累计胜场） `{id}` | 非观战者 |

### 会话身份

每个浏览器**标签页**生成一个 UUID，存入 `sessionStorage`：

- 刷新页面：身份保留 → 重连后自动回到原槽位
- 关闭标签页：身份丢失 → 下次打开是新会话
- 两个标签页：独立身份，可同时扮演 P01 + P02（适合本机调试）

### 角色分配

```
连接 1 ─▶ PLAYER 01  (绿色 #CCFF00)
连接 2 ─▶ PLAYER 02  (品红 #FF2E88)
连接 3+ ─▶ SPECTATOR (可看不能动)
```

### 断线宽限

玩家断线（关页 / 网络中断）后：

1. 服务端保留槽位 **15 秒**
2. 同一 sessionId 在宽限期内重连 → 恢复原槽位
3. 超过 15 秒未回 → 槽位释放，下一个 spectator 刷新页面可补位

### SSE 快照格式

```jsonc
{
  "board": [[0,0,...], ...],     // 15x15 二维数组，0=空 / 1=P01 / 2=P02
  "current": 1,                  // 当前回合方
  "history": [{"r":7,"c":7,"p":1}, ...],
  "finished": false,             // 是否已结束
  "winLine": [{"r":7,"c":7}, {"r":7,"c":11}] | null,
  "wins": [2, 1],                // 累计胜场 [P01, P02]
  "p1Online": true,
  "p2Online": false,
  "p1Claimed": true,             // 槽位是否被占（含离线宽限）
  "p2Claimed": false,
  "spectators": 0,
  "youAre": "p1",                // 仅当前客户端可见
  "serverTime": 1715760000000
}
```

## 玩法规则

- 棋盘 **15 × 15**
- 棋子下在**交叉点**，不是格子里
- **P01（柠绿）先手**，双方轮流
- 最先在横、竖、任一对角方向上形成**连续 5 子**者获胜
- **无禁手规则**（自由式 / Free-style）—— 黑棋长连、双三、双四均合法
- 棋盘 225 格全部填满仍无 5 连则视为平局（当前版本未特殊处理平局，会一直停在最后一手）

## 常见问题与注意事项

### 🔥 连接相关

**对手打不开 Network URL？**

1. 确认两台设备**连同一 Wi-Fi**（手机热点也可以，但确认两台都连到了热点上）
2. 检查 Mac 系统设置 → **防火墙**：若开启，需允许 `node` 接受入站连接
   - 系统设置 → 网络 → 防火墙 → 选项 → 允许 `node`
3. 公司 / 校园网络可能开启 **客户端隔离（AP Isolation）**，导致同网段设备互不可见 → 用手机开热点测试
4. 服务端打印了多个 Network IP，挨个尝试。`198.18.0.1` 通常是虚拟网卡（如 ClashX、Docker），无效

**显示 `RECONNECTING…`？**

- EventSource 自动重连，等几秒一般会恢复
- 如长时间不恢复，检查服务端是否还在运行，或刷新页面

**第三个人加入了，但我变成观战者？**

- 槽位先到先得，前两个连接占据 P01/P02
- 想换角色：关掉 P01 或 P02 的页面，等 15 秒宽限期过后，刷新观战者页面即可补位

### 🎮 游戏相关

**点了棋盘没反应？**

可能原因（顶部 toast 会提示）：
- "等待对手落子" —— 不是你的回合
- "观战中 · 不能落子" —— 你是 spectator
- 鼠标 cursor 是 `not-allowed` —— 棋盘锁定中（对手未连上 / 游戏结束 / 不是你的回合）

**Undo 会撤销几步？**

每次撤销**一步**。可以连续按 `U` 撤多步。游戏已结束时禁止撤销。

**胜场计数被重置了？**

- 累计胜场在服务端内存里 —— **重启 `node server.js` 会清空**
- 浏览器刷新 / 重开不会重置

### 🔒 安全注意

- **本服务仅用于内网对战**，未做任何鉴权 / 加密
- 任何能访问 `http://<your-ip>:8080` 的人都能加入或观战
- **不要把端口暴露到公网**（不要做端口转发 / frp 之类的）
- 如果在咖啡馆等公共 Wi-Fi 下使用，旁边的人理论上可以加入你的对局

### 🐛 已知限制

- 不支持**平局**自动判定（225 子下满仍无连珠时不会提示）
- 不支持**禁手规则**（黑棋长连 / 双三 / 双四均合法）
- 不支持**自定义昵称**
- 不支持**悔棋需对方同意**（任一玩家可单方面撤销）
- 不支持**聊天**
- 不支持**多房间**（整个服务端只有一个棋局）

## 二次开发

### 修改棋盘大小

`server.js` 第 9 行：

```js
const N = 15;   // 改成 19 即为标准围棋盘
```

同时修改 `gomoku.html` 中的 `const N = 15;` 与坐标轴标签。

### 修改宽限期

`server.js`：

```js
const RECONNECT_GRACE_MS = 15000;   // 毫秒
```

### 修改配色

`gomoku.html` 中 `:root` CSS 变量：

```css
:root {
  --bg: #0a0a0a;
  --lime: #ccff00;      /* P01 主色 */
  --magenta: #ff2e88;   /* P02 主色 */
  --cyan: #00e5ff;
}
```

注意 Canvas 绘制的棋子颜色是**硬编码字符串**，需同步修改 `drawStone()`、`checkWin` 后的胜利连线颜色等位置。

### 加禁手规则

在 `server.js` 的 `handleMove()` 中，落子前先调用一个 `isForbidden(r, c, p)` 校验，命中则返回 `{ok:false, err:'forbidden'}`。

### 加聊天

新增 `POST /chat` 端点，把消息塞进 state 的循环缓冲，broadcast 时一并下发。前端在 console 面板加输入框。

## 附：random_number_picker.py

一个独立的 Python CLI 小工具，与五子棋无关。

```bash
python3 random_number_picker.py
```

让用户输入 10 个数字（支持一次输入空格分隔，或逐个输入），然后提供 3 种随机抽取模式：

1. 抽 1 个
2. 抽多个（不重复，`random.sample`）
3. 抽多个（可重复，`random.choice` × N）

> 此文件是仓库的早期内容，保留作历史参考。功能存在一些已知的细节问题（如递归实现"重置"会累积调用栈、批量输入解析失败会丢失已 split 数字等），如需修复请见之前的代码评审建议。
