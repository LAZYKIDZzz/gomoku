一个**新粗野主义 × 赛博**风格的实时五子棋对战网页，零外部依赖。
两人在**同一 Wi-Fi**下打开同一链接即可开战。仓库里另附一份 Python 命令行小工具 `random_number_picker.py`。

## 项目内容

```
claude-test/
├── README.md                ← 本文件
├── gomoku.html              ← 前端：登录 + 棋盘 + 排行榜（Canvas + SSE + fetch）
├── server.js                ← 后端：Node.js 零依赖 HTTP + SSE 服务端
├── players.json             ← 运行时生成的玩家档案（已 .gitignore）
└── .gitignore
```

| 文件 | 行数 | 说明 |
|------|------|------|
| `server.js` | ~330 | 单文件后端：HTTP 静态分发 + SSE 实时广播 + REST 落子 / 撤销 / 重开 / 名称查询。仅依赖 Node.js 标准库。 |
| `gomoku.html` | ~1200 | 单文件前端：HTML + CSS + Canvas 棋盘 + 登录 + 排行榜。无构建步骤、无打包工具。 |
| `players.json` | 自动 | 持久化玩家档案（score / wins / losses / streak / bestStreak / totalGames / lastSeen）。删除即重置全部历史。 |

**核心特性**

- 🌐 **真正的两人联机** —— 同一 Wi-Fi 下分享链接即可对战
- 🪪 **玩家称号 Handle** —— 支持中文 / 字母 / 数字 / `_-·`，2-16 字符，跨会话识别同一玩家
- 🏆 **持久化分数体系** —— 胜 +10、连胜加成、速胜加成、负 -5；档案落盘 `players.json`
- 📊 **实时排行榜** —— Top 10 按分数排名，第一名描金，当前玩家高亮
- ⚡ **零依赖** —— `node server.js` 直接跑，不需要 `npm install`
- 🎨 **大胆视觉** —— 新粗野主义，电光柠绿 / 霓虹品红 / 描金双主色 + 强调，巨幅展示字
- 🔄 **断线重连** —— 15 秒宽限期内刷新 / 重连可保住槽位
- 👀 **观战模式** —— 第三个连接自动成为观战者，可看完整对局与排行榜
- 🎯 **服务器权威** —— 所有规则判定 + 计分在服务端，客户端只渲染快照

## 快速开始

### 环境要求

- **Node.js ≥ 14**（用于运行服务端）
- 任何现代浏览器（Chrome / Firefox / Safari / Edge），支持 `EventSource` 与 ES2017+
- 两台设备需连接 **同一 Wi-Fi**（或可互通的内网）

### 启动服务器

```bash
node server.js
```

启动后控制台会打印：

```
  GOMOKU // PROTOCOL SERVER
  ────────────────────────────────────────────────
  Local    →  http://localhost:8080
  Network  →  http://192.168.1.42:8080      ← 把这个发给对手
  Network  →  http://192.168.8.233:8080
  ────────────────────────────────────────────────
  Records  →  /your/path/players.json
  Players  →  3 registered
  把 Network 链接发给对手 (需连同一 Wi-Fi)，打开即可对战。
  Ctrl+C 退出。
```

### 自定义端口

```bash
PORT=9000 node server.js
```

### 开始对战

1. 第一位玩家打开 `Local` URL（或 Network URL），弹出 **PLAYER REGISTRATION** 注册卡
2. 输入称号（2-16 字符，例如 `CYBER_RONIN` / `霓虹武士`）或点击建议 chip
3. 点击 **ENTER ARENA · 进入对局** → 自动占据 P01 槽位
4. 把任一 **Network URL** 发给对手（在同一 Wi-Fi 下）
5. 对手注册自己的称号后自动成为 P02
6. 棋盘解锁，**P01（电光柠绿）先手**
7. 5 子连珠即获胜，弹出胜利动画显示分数明细，底部排行榜实时更新

> 第 3 个及以后的连接会自动变为 **SPECTATOR**（观战），可以看完整对局与排行榜，不能落子。

## 玩家身份 · Handle

### 称号格式

- 长度 **2-16 字符**
- 允许字符集：中文 / 英文字母 / 数字 / `_` / `-` / `·`
- 大小写不敏感：`Alice` / `ALICE` / `alice` **视为同一玩家**，但显示时保留原始大小写

### 存储

- 客户端：`localStorage.gomoku_name` 保存当前称号，下次自动登录
- 服务端：`players.json` 以小写名为主键存档，包含分数 / 战绩 / 连胜等
- **会话 token**：`sessionStorage.gomoku_id` 仅用于 15 秒断线重连，关闭标签页就丢

### 识别逻辑

| 场景 | 行为 |
|------|------|
| 新称号首次进入 | 创建档案，分数从 0 开始 |
| 已有称号再次登录 | 拉取历史档案，注册卡显示 **WELCOME BACK** 与上次战绩 |
| 多设备同名 | 视为同一玩家，共享分数 / 槽位（适合手机 + 电脑同步玩） |
| 刷新页面 | 15 秒内自动重连同一槽位 |

### 切换称号

- 点击右上角 ID 徽章（YOU · XXX）→ 重新弹出注册卡
- 或手动清空 `localStorage.gomoku_name` 后刷新

## 分数体系

### 公式

| 事件 | 分数变化 |
|------|----------|
| 胜利基础 | **+10** |
| 第 N 连胜（N ≥ 2） | 额外 `+min((N-1) × 2, 10)` |
| 速胜（总步数 ≤ 18） | 额外 **+5** |
| 失败 | **−5**（连胜归零） |

> 单局最高加分 = 10 + 10 + 5 = **+25**（达成 6 连胜起的速胜局）

### 示例

| 局况 | 计算 | 净增分 |
|------|------|--------|
| 第 1 局赢，11 手成局 | 10 + 0 + 5 | **+15** |
| 第 2 连胜，14 手 | 10 + 2 + 5 | **+17** |
| 第 5 连胜，30 手 | 10 + 8 + 0 | **+18** |
| 第 6 连胜起，12 手 | 10 + 10 + 5 | **+25** |
| 任一负局 | -5 | **−5** |

### 字段

`players.json` 中每位玩家记录：

```jsonc
{
  "alice": {
    "name": "Alice",        // 原始显示名
    "score": 32,             // 累计分数（可为负）
    "wins": 2,
    "losses": 0,
    "streak": 2,             // 当前连胜（负局重置为 0）
    "bestStreak": 2,         // 历史最高连胜
    "totalGames": 2,
    "lastSeen": 1715760000000,
    "createdAt": 1715760000000
  }
}
```

### 重置全部分数

```bash
rm players.json
```

下次启动服务端会自动重建空档案。**该文件已 `.gitignore`，不会进入版本控制。**

## 排行榜

### 显示

主网格下方有一块**全宽 LEADERBOARD 面板**，列出 Top 10：

| 列 | 含义 |
|----|------|
| `RANK` | 排名，第 1 名描金 `★` |
| `HANDLE · 称号` | 玩家称号，前面有 ● 在线 / 灰点离线 指示 |
| `SCORE · 分` | 累计分数；负数显示为锈红 |
| `W - L` | 胜场 - 负场 |
| `RATE · 胜率` | 胜场 / 总场数 |
| `STREAK · 连胜` | 🔥 N 当前连胜，N=0 时显示 `— 0` |

### 排序

```
SCORE 降序 → 同分时 WINS 降序 → 再同分时 LOSSES 升序
```

### 实时同步

排行榜与游戏状态共享同一条 SSE 通道，每次落子 / 胜负 / 玩家上下线都会自动刷新。无需轮询。

### 当前玩家高亮

你自己在表格中会有：
- 柠绿底色 + 左侧粗竖线
- 名字后面 `[YOU·你]` 小角标

## 架构与协议

### 通信模型

```
┌─────────────┐   GET /events?name=…&id=… (SSE)  ┌──────────────┐
│             │ ◀─────────────────────────────────│              │
│  Browser A  │                                   │              │
│  (P01)      │   POST /move / /undo / /restart   │              │
│             │ ─────────────────────────────────▶│   Node.js    │
└─────────────┘                                   │   server.js  │
                                                   │              │
┌─────────────┐                                   │  权威状态机  │
│  Browser B  │ ◀── SSE broadcast ────────────────│  + 计分      │
│  (P02)      │ ─── POST /move ──────────────────▶│  + 排行榜    │
└─────────────┘                                   │              │
                                                   │   ↓ 持久化   │
                                                   │ players.json │
                                                   └──────────────┘
```

服务端在每次状态变化后向**所有连接的客户端**广播完整快照（含棋盘、玩家信息、排行榜 Top 10）。游戏结束时额外附带 `lastEvent` 用于触发分数飘字 + 胜利弹窗。

### HTTP 端点

| 方法 | 路径 | 用途 | 鉴权 |
|------|------|------|------|
| `GET` | `/` | 返回 `gomoku.html` | 无 |
| `GET` | `/events?name=<handle>&id=<sessionId>` | 建立 SSE 长连接 | 校验 name 格式 |
| `GET` | `/leaderboard` | 拉取 Top 10 排行榜 | 无 |
| `POST` | `/check-name` | 查询称号是否已存在 + 历史战绩 `{name}` | 无 |
| `POST` | `/move` | 落子 `{id, r, c}` | 必须是当前回合方 |
| `POST` | `/undo` | 撤销最近一手 `{id}` | 非观战者 |
| `POST` | `/restart` | 重置棋盘（保留累计胜场） `{id}` | 非观战者 |

### 会话 / 身份双层标识

| 标识 | 存储位置 | 作用 |
|------|----------|------|
| **handle**（玩家称号） | `localStorage.gomoku_name` | 跨会话、跨设备的玩家身份 |
| **sessionId**（会话 token） | `sessionStorage.gomoku_id` | 当前标签页的连接令牌；用于 15 秒断线重连和 POST 鉴权 |

POST 请求只发 sessionId，服务端通过 `sessionId → name → role` 查表。

### 角色分配

```
连接 1 ─▶ PLAYER 01  (柠绿 #CCFF00)
连接 2 ─▶ PLAYER 02  (品红 #FF2E88)
连接 3+ ─▶ SPECTATOR (可看不能动)
```

槽位释放：玩家断线 → 等待 15 秒 → 若同一 handle 没回来则释放，下一个 spectator 刷新页面可补位。

### SSE 快照格式

```jsonc
{
  "board": [[0,0,...], ...],     // 15x15，0=空 / 1=P01 / 2=P02
  "current": 1,
  "history": [{"r":7,"c":7,"p":1}, ...],
  "finished": false,
  "winLine": [{"r":7,"c":7}, {"r":7,"c":11}] | null,
  "gameStartTime": 1715760000000,
  "p1": {
    "name": "Alice", "key": "alice",
    "score": 32, "wins": 2, "losses": 0,
    "streak": 2, "bestStreak": 3, "games": 2
  },
  "p2": { /* 同上 */ } | null,
  "p1Online": true, "p2Online": false,
  "p1Claimed": true, "p2Claimed": true,
  "spectators": 0,
  "leaderboard": [ /* Top 10 公开记录 */ ],
  "totalPlayers": 4,
  "youAre": "p1",                // 仅当前客户端可见
  "youKey": "alice",
  "youName": "Alice",
  "serverTime": 1715760000000,
  "lastEvent": null              // 游戏结束时附带分数事件
}
```

游戏结束时 `lastEvent`:

```jsonc

  "winnerSlot": 1,

  "moves": 11,

    "delta": 15,
    "base": 10, "streakBonus": 0, "quickBonus": 5,
    "streak": 1, "score": 15
  },
  "loser": {
    "name": "Bob", "key": "bob",

  }

## 玩法规则

- 棋盘 **15 × 15**
- 棋子下在**交叉点**，不是格子里
- **P01（柠绿）先手**，双方轮流
- 最先在横、竖、任一对角方向上形成**连续 5 子**者获胜
- **无禁手规则**（自由式 / Free-style）—— 黑棋长连、双三、双四均合法
- 棋盘 225 格全部填满仍无 5 连则视为平局（当前版本未特殊处理平局，会一直停在最后一手）

## 常见问题与注意事项

### 🔥 连接相关

**对手打不开 Network URL？**

1. 确认两台设备**连同一 Wi-Fi**（手机热点也可以，但确认两台都连到了热点上）
2. 检查 Mac 系统设置 → **防火墙**：若开启，需允许 `node` 接受入站连接
   - 系统设置 → 网络 → 防火墙 → 选项 → 允许 `node`
3. 公司 / 校园网络可能开启 **客户端隔离（AP Isolation）**，导致同网段设备互不可见 → 用手机开热点测试
4. 服务端打印了多个 Network IP，挨个尝试。`198.18.0.1` 通常是虚拟网卡（如 ClashX、Docker），无效

**显示 `RECONNECTING…`？**

- EventSource 自动重连，等几秒一般会恢复
- 如长时间不恢复，检查服务端是否还在运行，或刷新页面

**第三个人加入了，但我变成观战者？**

- 槽位先到先得，前两个连接占据 P01/P02
- 想换角色：关掉 P01 或 P02 的页面，等 15 秒宽限期过后，刷新观战者页面即可补位

### 🪪 称号相关

**我的称号被别人占用了？**

不会。同名 = 同一玩家。如果你想避免冲突，加个独特后缀（`Alice_007` / `黑曜棋手II`）。

**忘了上次用什么称号？**

打开浏览器 DevTools → Application → Local Storage → 查看 `gomoku_name`。
或重新输入想到的几个名字，注册卡会显示 **WELCOME BACK · 欢迎回来** 提示。

**两台设备分数不同步？**

不会发生。服务端按 handle 小写归并存档，无论你从哪台设备登录同一称号，都看到同一份分数。

### 🎮 游戏相关

**点了棋盘没反应？**

可能原因（顶部 toast 会提示）：
- "NOT YOUR TURN · 等待对手落子" —— 不是你的回合
- "SPECTATOR · 观战模式不可落子" —— 你是 spectator
- 鼠标 cursor 是 `not-allowed` —— 棋盘锁定中（对手未连上 / 游戏结束 / 不是你的回合）

**Undo 会撤销几步？**

每次撤销**一步**。可以连续按 `U` 撤多步。游戏已结束时禁止撤销。撤销**不影响**已结算的分数。

**胜场计数被重置了？**

- 玩家分数与战绩**持久化在 `players.json`**，服务端重启不会清空
- 唯一清空方式：`rm players.json` 然后重启

### 🔒 安全注意

- **本服务仅用于内网对战**，未做任何鉴权 / 加密
- 任何能访问 `http://<your-ip>:8080` 的人都能注册任意称号、加入或观战
- **不要把端口暴露到公网**（不要做端口转发 / frp 之类的）
- 称号无独占机制 —— 别人理论上可以用你的称号登录"代打"。同 Wi-Fi 下的对手默认信任
- `players.json` 包含玩家称号与战绩，已加入 `.gitignore`，但若手动备份请注意隐私

### 🐛 已知限制

- 不支持**平局**自动判定（225 子下满仍无连珠时不会提示）
- 不支持**禁手规则**（黑棋长连 / 双三 / 双四均合法）
- 不支持**昵称独占**（同名共享身份）
- 不支持**悔棋需对方同意**（任一玩家可单方面撤销）
- 不支持**聊天**
- 不支持**多房间**（整个服务端只有一个棋局，但排行榜跨场次累计）
- 不支持**对局回放**

  WIN_BASE: 10,           // 每胜基础分
  LOSS: -5,               // 每负扣分
  STREAK_PER_WIN: 2,      // 第 N 连胜额外: min((N-1)*PER, MAX)
  STREAK_MAX: 10,
  QUICK_WIN_BONUS: 5,     // 总步数 <= 阈值时奖励
  QUICK_WIN_MOVES: 18,
};
```

想要更高强度的对抗？把 `LOSS` 改成 `-10`，或加 `KO_BONUS`（连续 3+ 胜后封顶时再加分）。

新增 `POST /chat` 端点，把消息塞进 state 的循环缓冲，broadcast 时一并下发。前端在 console 面板加输入框。

### 加成就 / 徽章

在 `settleScores()` 里检测条件后写入 `records[key].badges = [...]`，broadcast 时一起发，前端在玩家卡或排行榜行渲染。例如：
- `FIRST BLOOD` —— 首胜
- `KILLSTREAK 5` —— 5 连胜
- `SPEEDRUNNER` —— 累计速胜 10 次
- `COMEBACK KING` —— 在连负 3 局后反超

### 对局回放

在 `settleScores()` 中把 `state.history` 存到 `records[key].replays = [...]`（按时间裁剪保留最近 N 局），新增 `GET /replay/:id` 返回某局棋谱，前端做一个回放播放器。
